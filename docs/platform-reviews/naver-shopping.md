# 플랫폼 정책 검토: 네이버 쇼핑 검색 API

> 검토일: 2026-11-18 · 절차: [architecture.md §6](../architecture.md#6-데이터-수집-정책-검토-절차)
> 결론: **사용하지 않음** — 가격 이력 저장 목적과 약관이 맞지 않음

## 1. 검토 배경

무신사는 자동 수집이 금지되어 있어([musinsa.md](musinsa.md)), 공식 API로 가격을 자동 수집하는 대안으로 네이버 쇼핑 검색 API를 검토했다.

## 2. 약관 (NAVER API 서비스 이용약관, NAVER API HUB, 2026-06-25 시행) — 원문 확인

- **7.3 ③**: "API 서비스를 이용하여 취득한 정보(…)를 다음의 예시와 같이 본 약관에서 허용한 범위를 넘어서서 무단으로 복제, 저장(캐시 행위 포함), 가공, 배포 등 이용하거나 제3자에게 제공하는 행위"를 금지한다.
  - 예시: "기타 각 API의 제공 취지나 목적에 맞지 않게 API 제공 정보를 저장하거나 이용하는 행위"
- **7.3 ⑤**: "데이터를 추출 저장하는 등의 목적으로" 다수의 클라이언트 아이디로 호출하는 행위 금지.
- **7.1 ③**: 애플리케이션 사용자로부터 API 이용 대가를 받는 행위 금지.

## 3. 검색 API 개별 조건 — 보도 기준 (개별 약관 원문은 확인하지 못함)

- 검색 API는 "애플리케이션에서 네이버 검색 결과를 그대로 보여주는 목적"으로만 이용 가능.
- 결과 보관: 서버는 이력 조회 목적이라도 최대 21일로 제한된다고 보도됨.
- 검색 API 3종 신규 신청 중단(2026-07-31), 기존 이용자는 2027-06-30까지 유예, NAVER API HUB 로 이관.

## 4. 이 서비스와의 충돌

| 서비스 요구 | 약관 | 판단 |
|---|---|---|
| 수집 가격을 별도 DB에 수개월 저장 | 목적 외 저장 금지 (7.3 ③), 서버 보관 21일 (보도) | 충돌 |
| 30·90일 최저가를 계산해 표시 | 검색 결과를 "그대로" 보여주는 목적 | 충돌 |
| 옵션(사이즈·색상)별 가격 관리 | 상품 단위 최저가만 제공 | 기능상 부적합 |

## 5. 결론

- 네이버 쇼핑 검색 API 는 사용하지 않는다.
- 이 프로젝트의 가격 수집 방식은 **수동 입력 + 북마클릿**으로 확정한다 (출처 `manual`).
- 자동 수집기(어댑터·스케줄러, PRD F2-3·F2-4)는 구현하지 않는다. 수동 기록의 부담은 "오늘 확인할 상품" 목록으로 줄인다.

## 6. 재검토 조건

- 네이버가 가격 이력 저장을 허용하는 별도 상품(예: 쇼핑 데이터 제휴)을 제공하는 경우
- 개별 약관 원문에서 위 3절과 다른 조건이 확인되는 경우
